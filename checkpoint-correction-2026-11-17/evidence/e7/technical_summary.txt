Ablation interpretation
The historical no_anchor mode disables both protected-root equality/binding and final anchor verification. It is retained as a backwards-compatible input alias; the explicit name and result label are no_root_binding_or_anchor. The attack repeats a constructed attacker-chosen root/payload response for each fixture. It is not a separately measured authentic-stale-checkpoint experiment. The safe and joint-ablation decisions use the same test frame.

Metric definitions and compatibility
- deterministic_expected_reject_accepts: accepted constructed frames whose expected outcome is rejection. This includes invalid evidence or representation checks even when the returned block/root are canonical.
- noncanonical_data_accepts: accepted block or root differs from the fixture's canonical block/root. This matches the formal wrong-block/root event in this fixed-fixture harness, not a complete security proof.
- deterministic_policy_only_accepts / unsafe_policy_only_accepts: accepted expected-reject frames with canonical block/root.
- fuzz_detected_violations / legacy fuzz false_accepts: accepted noncanonical block/root OR metadata mismatch.
- metadata_policy_accepts is an overlapping flag; metadata_only_accepts is the disjoint canonical-block/root part.
- fuzz_accepted_canonical_metadata_valid_mutations: accepted fuzz mutations with no detected block/root/metadata violation. This label states what the oracle checks; it is not an independent certificate-validation proof.
- tested_inputs: deterministic expected-reject frames plus ALL fuzz executions. Fuzz mutations can be benign, so the total is no longer called malicious_responses in the combined summary or fuzz rows. Deterministic/ablation malicious_responses fields remain because those frames are deliberately expected to be rejected.
- false_accepts is retained as a documented legacy aggregate of different test oracles. New explicit counters accompany it. Existing historical rows without the new counters yield null/unknown, never fabricated category totals.
- No pooled zero-event probability bound is generated across deterministic tests and adaptive fuzz executions, because they have different oracles and fuzz mutations need not be malicious. Existing per-family empirical output was not otherwise redesigned.
Output schema version is 2 for changed E7 raw/fuzz and combined summaries. Internal guard count is now 42 due to the two explicit checkpoint/mode guards; old 40/40 and 338/652 coverage values describe the old publication version only.
